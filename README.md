# AI Workflow Automation Platform

> 用 n8n + 大模型，把企业每天涌进来的**客户咨询、表单提交、邮件、文档**自动接住、听懂、分类、记录、通知到人。
> 不是一个技术 Demo，而是一套**已经把"人工分拣 + 手动录入 + 挨个打电话"这条老流程跑通成分钟级闭环**的企业级自动化方案。

---

## 它在解决什么业务问题

企业每天会在官网表单、邮件、企业微信、客服后台收到大量客户进线。过去这些事情靠人做：

- 客服早上挨个后台翻消息；
- 凭经验判断"这是售前还是售后、客户急不急"；
- 手动复制到 Excel，字段格式还不统一；
- 微信吼一声让对应同事接，紧急的事经常因为人在开会被拖半天；
- 等客户在社交平台发了投诉，才知道出事了。

这套工作流把上面整条链路自动化掉：**客户说完话，30 秒内被听懂、被分好类、写进飞书表格、卡片 @ 到负责人，高危的红色置顶。**

## 业务流程（不是技术流程）

```
客户在任何入口留了一句话
        ↓
   ① 统一接收（Webhook）
        ↓
   ② LLM 听懂：客户要什么？生气没生气？急不急？
        ↓
   ③ AI 分类：售前 / 售后 / 技术 / 账单 / 商务 / 投诉 / 其他
        ↓
   ④ 自动写一段 60 字摘要，让负责人扫一眼就懂
        ↓
   ⑤ 生成一条结构化工单（工单号、客户、字段齐全）
        ↓
   ⑥ 实时同步到飞书多维表格 / 业务数据库
        ↓
   ⑦ 按紧急度给负责人发飞书卡片（红=高危 / 橙=紧急 / 蓝=普通）
```

人从此只做一件事：**处理真正需要专业判断和客户沟通的部分**。搬运、读、分、录、喊，全部交给系统。

## 关键能力（对应需求里的 4 个"增加"）

| 需求 | 本方案实现 |
|---|---|
| AI 分类节点 | ③ AI 智能分类：7 类业务自动归口，带结构化输出强约束 |
| LLM 分析节点 | ② LLM 需求分析：意图 / 情绪 / 紧急度 / 期望动作 四元组 |
| 自动生成摘要 | ④ 自动生成摘要：≤60 字，负责人扫读即可 |
| 自动通知 | ⑦ 自动通知负责人：飞书交互卡片，颜色随紧急度变化，高危秒触达 |

## 怎么跑起来

1. 在 n8n 里 **Workflows → Import from File**，选 `workflows/customer-inbox-ai-automation.json`；
2. 配好两个凭据：
   - OpenAI 凭据（接 ②③④ 三个 LLM 节点）；
   - 飞书自建应用，拿到 `app_id / app_secret`，开通 `bitable:app` 和 `im:message` 权限；
3. 在环境变量里填：
   - `FEISHU_BITABLE_APP_TOKEN` / `FEISHU_BITABLE_TABLE_ID`
   - `FEISHU_OWNER_USER_ID`（默认通知谁）
4. 激活 Webhook，对外暴露地址 `POST /webhook/customer-inbox`；
5. 用 curl 发一条测试：

```bash
curl -X POST https://your-n8n/webhook/customer-inbox \
  -H "Content-Type: application/json" \
  -d '{"name":"张先生","contact":"13800000000","source":"官网表单","message":"我上周买的设备今天开不了机，客户马上要验收，请今天必须解决！"}'
```

预期：飞书多维表格多一行、负责人飞书收到一张红色卡片，回执里带回 `ticket_id`。

## 适用场景

- 有官网/小程序/客服后台，每天要处理大量客户进线的公司；
- 客服团队被"搬消息、抄数据、派单"占掉大量时间；
- 老板想有一张"今天客户在说什么、情绪好不好"的实时看板；
- 已经在用飞书，想让数据直接进多维表格、通知直接到飞书卡片，不再引入新系统。
